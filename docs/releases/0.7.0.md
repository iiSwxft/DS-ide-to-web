## DeepSeek++ 0.7.0

The main thrust of 0.7.0 is not adding a few standalone entry points, but moving DeepSeek++ from enhancing the DeepSeek web page to an in-browser AI Agent workbench that can carry project tasks over the long term. This release completes the three layers most critical to sustained work: reusable project context, downloadable deliverables, and a tool execution process users can review and take over.

### Key Changes

- **Project context becomes the task entry point**: repositories, web pages, local files, and manual notes can be organized into a project library, and only the fragments relevant to the current task are brought into the conversation, reducing repeated pasting of background.
- **Answers can become file artifacts**: adds single-file and project-bundle artifacts, suited for saving scripts, Markdown, JSON, HTML, small prototypes, or document collections so DeepSeek output flows into real workflows more easily.
- **Tool execution suits human-AI collaboration better**: sandbox confirmation, Skill drafts, memory import preview, saved snippets, and prompt controls are consolidated so users can review, edit, or reject at key steps instead of passively accepting automatically executed results.
- **The side panel feels more like a workbench**: side-panel chat, right-click scenarios, official API Key configuration, tool result restoration, and page navigation continue to be polished; after a refresh, tool blocks and Agent run blocks are restored under their corresponding replies.
- **Agent run feedback is more continuous**: Agent step content supports streaming Markdown rendering, so tables, headings, and highlights take shape as they are generated, and long output automatically follows to the bottom to show the latest progress.
- **Conversations and materials are easier to review**: saved items, history tags/search, code block downloads, single-message export, and image attachment manifests complete the everyday organizing toolkit, suited for turning one conversation into reusable material.
- **Platform and release quality continue to consolidate**: adds an Android WebView developer baseline and an asset staging pipeline without presenting it as a released mobile version; pre-release checks continue to cover English/Chinese, local tools, MCP, automation, multi-browser packaging, manifest policy, and release asset verification.

### Verification

- `npm run ci:quality`: covers workflow, production dependency audit, prompt freeze, compile, Vitest, English/Chinese i18n checks, automation, MCP / Shell / PoW smoke, multi-browser builds, manifest policy, packaging, and release asset verification.
- `npm run smoke:web`: covers web search and tool continuation prompts.
- `npm run build:android`: verifies Android WebView resource build and staging; APK builds and Android unit tests still require a local JDK.
- `npm pack --dry-run --workspace packages/shell-host`: confirms the contents of the Shell Host npm package.
